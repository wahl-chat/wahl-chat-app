# Uploaded party manifestos to ingest (prod).
#
# Object paths are identical to dev.txt — only the bucket differs, and that is
# resolved from ENV (see storage_paths._BUCKETS), so a document is promoted by
# uploading it to the prod bucket and copying its line here.
#
# One document per line, as a bucket object path:
#     public/{context_id}/{document-class}/{party_id}/{document-name}_{YYYY-MM-DD}.pdf
# A public Storage URL, a gs:// URI or a firebase/storage_data/... staging path is
# accepted too — all normalise to the same object path.
#
# The path carries the metadata: the election segment must be a context in
# firebase/firestore_data/{ENV}/contexts.json (which supplies region, level and the
# election date) and the party segment must be one of that context's parties.
#
# Document class — the folder between election and party. It decides whether
# Abgeordnetenwatch can ever replace the document:
#   wahlprogramme/    the programme the party runs on in this election. AW's
#                     election-program catalogue carries this class, so once AW
#                     publishes the same programme the uploaded copy is retired
#                     automatically on the next run (AW is the citable source).
#   parteidokumente/  anything we hold only BECAUSE the party published no
#                     Wahlprogramm — a federal Grundsatzprogramm, a Satzung. AW
#                     never publishes these, so they are never auto-retired.
#
# Dates. Every chunk's publish_date is the ELECTION date, whatever the filename
# says — that is what puts uploads and AW-sourced manifestos in the same campaign
# retrieval window. The filename suffix is the document's own date and is carried
# as meta.document_date for display only; it does not affect retrieval.
#
# This file is the COMPLETE statement of what should exist: delete a line and the
# next run removes that document's chunks from the corpus.
